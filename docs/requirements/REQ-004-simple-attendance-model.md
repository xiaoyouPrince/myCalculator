## 背景

REQ-001～003 的「日历角色 + 实际记录」双层编辑过于复杂，违反提效初衷。本需求收敛为简洁模型，**取代**对 `dayRole` / `rest-day-overtime` 的依赖。

## 目标

- 用户只选：**不上班**，或上班三类之一
- 工时申报：任何上班类型都按正常工作日规则统计（项目人力）
- **周末加班** vs **周末调休** 两本账分开

## 选项与算法

| 类型 | 工时 + 工时申报 | 加班时长（加班工资） | 调休额度 |
| --- | --- | --- | --- |
| 正常上班 | 正常规则 | 正常规则 | 0 |
| 周末加班 | 正常规则（与工作日同一套） | 正常规则 | 0 |
| 周末调休 | 正常规则 | **固定 0** | 本应按正常规则算出的加班时长，记入调休 |
| 不上班 | 0 | 0 | 0 |

## 范围

1. 去掉录入面板的 `dayRole` / 「按日历默认」
2. `WorkLogKind` 收敛为：`work` / `weekendOvertime` / `weekendCompensatory` / `off`；旧 kind / dayRole 加载时兼容迁移
3. `WorkMetrics` 增加 `compensatoryLeaveHours`；默认计算规则消化三类上班
4. 月格短标签与底色简化；详情不再展示日历角色
5. CSV：去掉「日历角色」，增加「调休额度」；下线或移除 `rest-day-overtime` 规则（避免再干扰）
6. 更新 README / 计算规则指南 / 扩展说明；REQ-003 标为已取消（被本需求取代）

## 不做

- 年假/病假等细分标签
- 调休补班单独类型
- 浏览器扩展立刻消费调休字段

## 验收标准

- [ ] 录入只有「正常上班 / 周末加班 / 周末调休 / 不上班」，无日历角色
- [ ] 同组上下班：正常上班与周末加班数字一致（含加班）
- [ ] 同组上下班：周末调休申报与正常上班相同，加班为 0，调休额度 = 正常规则下的加班时长
- [ ] 旧数据能打开；旧请假类记为不上班
- [ ] 侧栏/导出能看到调休额度合计或列
- [ ] 构建通过
